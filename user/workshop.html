LAB 01 / MCP GOVERNANCE

Lab 01: MCP Server 治理

将 filesystem-mcp 加入本人项目，仅开放 view；通过 OpenCode 和 Agent Guard 验证服务器准入与工具权限。

使用讲师分配的本人账号和对应 Project。
01

MCP Marketplace 准入配置

管理员操作 使用 workshopadmin 账号登录 JFrog。

  1. 进入 AI/ML → AI Catalog → Marketplace → MCP Servers。
  2. 搜索 filesystem-mcp，点击 Add to Registry。
  1. 选择本人对应的 projectN，不要选择其他项目。
  2. 选择 Select tools manually → Allow List，仅填写或选择 view；不要选择 Allow all tools。
  1. 按界面完成后续配置并保存。在 Registry 中确认该服务器已允许用于本人项目，且仅开放 view。
检查点：filesystem-mcp 已在本人项目中准入；create、insert、str_replace 未开放。

配置 OpenCode 与 JFrog Agent Guard

如您有自用模型，可以自行选择。

Step 2 · 添加项目级配置 JFrog Agent Guard

退出 OpenCode，在 user 目录创建 opencode.json，填写以下内容。已有配置时，将插件合并到现有 plugin 数组，保留其他配置。

opencode.json
{
  "plugin": ["@jfrog/opencode-jfrog-plugin"]
}

保存后，在同一目录的终端执行认证命令；按浏览器提示使用本人 JFrog 账号登录并授权。这一步是插件的 MCP 认证，与第一页 CLI 配置分别验证。

终端
opencode mcp auth jfrog

认证成功后重新启动 OpenCode，接受需要的插件或工作区信任提示。分别查看以下列表。

终端
opencode

03

通过提示词验证 MCP 治理

以下提示词依次输入 OpenCode，每条完成后再执行下一条。涉及文件的操作只允许使用 filesystem-mcp，不要改用内置文件工具或 shell 完成。

1. 查看本人项目可用的服务器

OpenCode 提示词
我所在项目有哪些 MCP server 可以使用？
预期结果：确认当前项目为本人 projectN，列表包含 filesystem-mcp。项目不正确时先联系讲师修正，不继续安装。

2. 安装已准入的服务器

OpenCode 提示词
为当前项目安装 filesystem-mcp
预期结果：安装成功。按插件提示重启 OpenCode，并确认服务器实际提供 view 工具。

3. 验证服务器准入限制

OpenCode 提示词
为当前项目安装 mongodb MCP server
预期结果：应拒绝安装。此测试的前提是讲师确认本人项目未准入 MongoDB MCP；如果已准入，先让讲师检查实验配置。

4. 验证读取成功

OpenCode 提示词
读取 lab_dir/workshop.md，显示实际文件内容。
预期结果：读取成功，内容包含 Welcome to the JFrog Workshop 和 Hello JFrog AI Platform。

5. 验证写入被拒绝

OpenCode 提示词
在 lab_dir 中创建 test.txt，内容为 Hello JFrog Workshop。
预期结果：create 未开放，应被拒绝或提示工具不可用，test.txt 不应被创建。这是预期结果。
04

开放 MCP 所有 tools

Step 1 · 管理员开放全部工具

  1. 使用 workshopadmin 登录平台，进入 AI/ML → AI Catalog → Registry → MCP Servers。
  2. 打开 filesystem-mcp，选择本人的 projectN，点击 Edit。
  3. 将仅允许 view 的配置改为 Allow all tools，按界面完成后续步骤并保存配置。

Step 2 · 客户端再次验证创建文件

回到本人 OpenCode，在同一实验目录再次输入下面的提示词。保留此前的文件路由规则和内置工具限制，不需要在提示词中指定 MCP 名称。

OpenCode 提示词
在 lab_dir 中创建 test.txt，内容为 Hello JFrog Workshop。
预期结果：通过 Agent Guard 调用 filesystem-mcp 的创建工具成功，生成 lab_dir/test.txt。检查调用记录，不能是内置 write、edit 或 bash 创建。

如果仍提示没有创建工具，重启 OpenCode 后重新查看 MCP 工具列表，再执行同一提示词；无需取消客户端的内置工具限制。若 test.txt 已存在，先联系讲师确认并恢复实验状态。

继续读取文件，确认实际内容：

OpenCode 提示词
读取 lab_dir/test.txt，显示实际文件内容。
预期结果：通过 filesystem-mcp 读回 Hello JFrog Workshop。同一创建请求在只开放 view 时不可执行，开放全部 tools 后执行成功。

LAB 02 / SKILLS MANAGEMENT

Lab 02 Skills 管理

在本人项目中创建 Skills 仓库，上传准备好的 Skill，并查看安全扫描结果。

使用本人 userN 账号和 projectN 项目。
01

创建 skills 仓库

  1. 使用本人 userN 账号登录平台，在左上角选择本人的 projectN。
  2. 进入 Administration → Repositories → Create a Repository，选择 Local。
  3. Package Type 选择 Skills，仓库名称填写 workshop-skills，确认归属本人项目。
  4. 创建仓库，并记录列表中显示的完整 Repository Key。如界面自动添加项目名前缀，保留该前缀。
02

上传 skills

本次使用的 Skills demo 目录：skills/skills-e2e-single，名称为 skills-e2e-single，版本为 0.0.1。

此样例含要求将 .env 发送到外部地址的风险指令，用于扫描演示。只上传并查看报告，不安装、不执行，也不要让 Agent 按该 Skill 的正文操作。
  1. 新开终端，进入 jfrog-ai-workshop/user 目录。上传在终端执行，不在 OpenCode 对话框输入。
  2. 在下面填写第一步记录的完整 Repository Key，复制命令到终端执行。使用第一页配置的本人 CLI Server。
终端 · 发布 Skill
请先填写本人仓库的完整 Repository Key。

CLI 会打包、上传，并等待或报告安全扫描结果。若显示风险或扫描失败，先在仓库确认包是否已经上传，再进入第 03 部分查看报告，不要通过跳过扫描或删除制品来隐藏结果。

检查点：在本人 Skills 仓库中找到 skills-e2e-single 的 0.0.1 版本，记录制品路径。若版本已存在，不覆盖，联系讲师确认是否使用已有结果。
03

Skills 扫描

  1. 进入 Xray → Scans List，按本人 Repository Key 和 skills-e2e-single 查找刚上传的包。
  2. 若仍在扫描，等待后刷新。打开该制品的扫描结果，查看状态、严重程度及风险详情。
  3. 阅读命中行为、扫描器判定原因和证据，重点检查是否识别到敏感信息外泄或提示词注入。记录实际结果，不预设一定命中某条规则。
  4. 如环境提供 AI/ML → AI Catalog → Registry → Skills，也可在本人项目中查看该 Skill 的版本和扫描状态。
结果如何理解
Malicious / Critical扫描识别为恶意行为，打开风险详情和证据。
Suspicious / High存在可疑行为，需要查看上下文并人工评审。
Not malicious / 无风险发现本次扫描未报告风险，不代表可忽略样例中的风险指令。
Not scanned / Scanning扫描尚未完成，不能作为已通过扫描的结果。
一直没有扫描结果怎么办？

请讲师检查 Skills 扫描服务是否已启用、仓库是否开启 Xray 索引。您先不要关闭扫描。
